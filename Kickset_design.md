# Kikset — Design Document (v0.1)

*Phase-locked kick + bass synthesizer for psytrance / Goa. CLAP, modern C++, CMake. 30 Sep 2026.*
*Companion to `research/kick-bass-research.md`. Structure modelled on [Acidus](https://github.com/holstebroe/Acidus).*

---

## 1. Goals and non-goals

**Goal:** one instrument that produces a finished, rolling K‑B‑B‑B kick+bass groove at any tempo and key. It stays phase-coherent and balanced without manual nudging, sidechaining or re-tuning.

**Must have (v1)**
- Kick and bass generated by **one engine on one timeline**, synced to the host beat grid.
- **Phase-locked anchor points** at every 1/16 inside the beat. The kick's phase at those points is known exactly, and the bass starts on it.
- Non-linear **pitch and amplitude shape between anchors**, adjustable with a few knobs.
- **Automatic velocity ("Flow")** for good roll, plus per-step **emphasis** controls.
- A simple **four-step UI**: the kick is fixed on step 1 and steps 2–4 are bass toggles. It also has feel knobs and a wide one-beat scope that shows the kick and bass in different colours.
- Controllable non-linear analog drive/saturation on the kick (phase-safe).
- An analog-sounding bass voice (hard-reset saw/pulse → 4-pole ladder → VCA).
- An embedded click sample set for the kick transient.
- CLAP only; **no external libraries except CLAP** (plus OS windowing APIs for the GUI, as in Acidus).

**Non-goals (v1):** VST3/AU wrappers, sample import, pattern lengths other than one beat, melodic bass lines, glide/portamento (deliberately banned in the low end), multi-out routing (planned for v1.1).

## 2. Core concept: the beat voice

Everything happens inside one **beat** (a quarter note) split into four **steps** of one 16th each:

```
 step:     0          1          2          3          (0 of next beat)
 time:   t0=0       t1=T16     t2=2T16    t3=3T16      t4=T_beat
          |  KICK      |  BASS 1   |  BASS 2   |  BASS 3   |
          ^anchor A0   ^A1         ^A2         ^A3         ^A4
```

`T16 = 60 / (BPM · 4)` seconds, which is ≈103.4 ms at 145 BPM. The kick is always triggered at A0. Bass steps 1–3 are toggles (default all on = KBBB). Other patterns follow from the toggles: K‑B‑B (step 3 off), K‑‑B‑B (step 1 off, "gallop"), K‑‑B‑ (offbeat).

The beat voice is **deterministic**: given (tempo, root, parameters) every beat renders bit-identically. That is what gives the hypnotic, repeatable roll. It also allows the GUI to render a preview beat on its own thread.

### 2.1 The shared phase grid

Let `f0` be the kick's fundamental (the root in the kick octave, §5.1). Define the **grid phase** in cycles:

```
G(t) = φ_start + f0·t + X
```

`X` is the total number of extra cycles contributed by the kick's pitch sweep. Once the sweep has settled, the kick oscillator's phase is **exactly** `G(t)`. The anchors A1…A3 are the points `G(t_n)`. They are known analytically before the beat is rendered.

The bass oscillator (running at `f_b = f0 · 2^(oct) · 2^(interval/12)`) starts each note at a phase derived from the grid, so kick tail and bass fundamental are coherent by construction.

### 2.2 Why anchors are not trivial

`f0 · T16` is not an integer and changes with key and tempo. Examples: F1 @ 145 BPM = 4.52 cycles, G1 @ 150 = 4.90, A1 @ 140 = 5.89. So where the kick's phase sits when the first bass note starts is effectively random. Producers fix it by hand, per track. Kikset fixes it analytically.

### 2.3 Two phase modes

| Mode | Bass note start phase | Anchors locked | When to use |
|---|---|---|---|
| **Reset** (default, classic psy) | Every bass note hard-resets to the **target phase** `ψ` (knob, default 0°) | The **first active bass anchor** is locked by the solver (§3). The kick tail is auto-gated to end before the next anchor. | Classic hard-reset sound; identical attack on every note at any key/tempo |
| **Follow** | Each bass note starts at the grid phase `G(t_n) + ψ` | **All** anchors locked; kick tail and bass stay coherent for the whole beat | Long/boomy kicks overlapping the bass; maximal "one instrument" feel |

In both modes the solver makes the kick land on `ψ` at the first active bass anchor. That note's attack is therefore identical at every key and tempo. In Follow mode, notes 2 and 3 start at `ψ + n·f0·T16` (frac), which is constant for a given key/tempo but differs per step.

> Saw polarity: the bass uses a **falling** saw (`1 − 2φ`). Its fundamental is `+(2/π)·sin 2πφ`, i.e. in phase with the kick's sine. A rising saw would put the fundamentals 180° apart. The sub sine uses the same phase variable.

## 3. The anchor solver

### 3.1 Kick pitch model (segment 0)

The pitch sweeps from `f0·2^O` down to `f0` over the **settle span** `S·T16` (S ∈ [0.3, 1.0], default 0.8). Normalised time is `u = t / (S·T16)`:

```
f(t)  = f0 · 2^( O · s(u) )      for u < 1,     f0 afterwards
s(u)  = (1 − p) · ŝ(u, k) + p · ŝ(u, 8k)                   (1 at u=0 → 0 at u=1)
ŝ(u,k)= (e^(−k·u) − e^(−k)) / (1 − e^(−k))
```

Knobs: **Sweep** `O` (start pitch in octaves, 0–6), **Curve** `k` (1–30, higher = faster initial drop), **Punch** `p` (0–1, blend of an 8× faster "click" component), **Settle** `S`. The shape reaches exactly `f0` at the settle point, so it is continuous in frequency.

Extra cycles over the sweep: `X = f0 · S·T16 · ∫₀¹ (2^(O·s(u)) − 1) du`. Compute it with a 1024-point cumulative trapezoid table `C(u)`, then renormalise so `C(1) = X` exactly. The kick phase at any time is then `Φ(t) = φ_start + f0·(t − τ) + C(u)`. It is evaluated per sample from the table, never by accumulating `φ += f/fs`. That makes the anchor phase exact, not subject to integration drift.

### 3.2 What the solver does

Target: `frac(Φ(t_a) − ψ_a) = 0` at the first active bass anchor `t_a`. Here `ψ_a` is the target phase, and in Follow mode the bass simply adopts `Φ(t_a)`. The residual is `δ = wrap(Φ(t_a) − ψ_a)` ∈ (−0.5, 0.5] cycles. The solver also considers `δ ± 1` and picks the cheapest.

`δ` can be absorbed by several **adjusters**. Each has a local sensitivity `J_i = ∂Φ(t_a)/∂x_i`, found numerically, and a perceptual cost weight `w_i`:

| Adjuster `x_i` | Effect | Typical cost |
|---|---|---|
| Kick trigger nudge `τ` (± ms) | Kick moves slightly relative to the grid (the manual "nudge" trick) | Low for < 3 ms |
| Sweep depth `O` | Start pitch | Medium |
| Curve `k` / settle `S` | Sweep speed | Medium |
| Start phase `φ_start` | Click character | Low–medium |
| Bass onset shift | Bass moves (the other manual trick) | Medium |

Minimum-weighted-norm update, with W = diag(w): `Δx = W⁻¹Jᵀ (J W⁻¹ Jᵀ)⁻¹ δ`. Iterate Newton 2–4 times with numeric J until |δ| < 1e‑9 cycles, then clamp each adjuster to its range. If clamping blocks convergence, fall back to the next adjuster.

Prototype numbers (Python, O=3, k=12, p=0.3) show why a single adjuster is not enough. The natural extra cycles for a fast sweep are only ≈1.0–1.25. Forcing them to an integer by changing depth alone moves the start pitch by up to 0.35 octave (A1: 440 → 331 Hz). Spreading the correction across nudge, start phase and depth keeps each change small: a 0.2-cycle residual at 44 Hz is 4.5 ms of nudge alone, or ~1.5 ms plus small depth/phase changes.

**Lock Style** knob (macro over the weights): *Timing ↔ Tone*. Timing prefers nudges and keeps the drawn sweep. Tone keeps timing exact and reshapes the sweep.

The solver runs on the audio thread at each kick trigger. It needs only a few thousand flops, so there is no latency. Results are cached by (tempo, f0, params hash), so steady state costs nothing. The GUI shows the applied corrections as read-only meters: nudge in ms, Δstart pitch in cents, Δphase in degrees.

### 3.3 Anchors after the first

- **Follow:** automatically locked. After settling, the kick runs exactly at `f0`, and the bass starts on `G(t_n)`.
- **Reset:** the kick amplitude envelope is constrained to reach zero before the next active anchor (plus a 1–2 ms fade). A long kick in Reset mode therefore cannot cancel bass notes 2–3. The UI shows the "tail gate" point.

## 4. Envelope shape between anchors

All times are in **fractions of a 16th**, with a ms readout. Changing the tempo scales the groove.

**Kick amplitude:** a short attack (0.1–2 ms), then an optional **Fishtail** dip (snap → dip → boom; depth 0–1, placed at 5–25 % of T16). The body then decays with **Shape** `c` as `a(v) = (1 − v)^c` over **Length** `L` (0.5–2.5 × T16, default 1.05). `L` is measured from A0, so the tail end is pinned to the anchor grid. **Gel** (0–0.5 × T16) is the amount of kick tail allowed to overlap the first bass note. In Reset mode it is capped by the tail gate.

**Bass amplitude (per note):** attack 0–5 ms (dogoftears' "little attack"), then an exponential decay whose **Snap** time is a fraction of T16. **Gate** (0.3–0.95 × T16) ends the note with a 2 ms release. The note must be silent before the next anchor.

**Bass filter:** cutoff + **Env Mod** (octaves, 0–6) with an exponential decay **F.Decay** as a fraction of T16. Research says filter speed is a *groove* parameter, so F.Decay is on the main panel.

Envelopes use RC-style exponential curves (analog feel), computed in closed form per sample from note-relative time. That keeps them deterministic.

## 5. Synthesis

### 5.1 Pitch and key

- **Root** comes from the Key knob (C…B), or from the last held MIDI note if one is present.
- **Kick f0:** the root's pitch class placed in the window [38, 76) Hz, plus **Kick Tune** ±12 semitones. Examples: F → 43.7 Hz, G → 49 Hz, C → 65.4 Hz.
- **Bass pitch:** `f0 · 2^(Bass Octave)` (0 or +1) × **Interval** (unison default; 2nd/3rd/4th/5th options, per the ModWiggler tip).
- Pitch is fixed per note. No glide.

### 5.2 Kick voice

- **Body:** a sine from the analytic phase `Φ(t)`, computed in double precision.
- **Analog drive / saturation** (see §5.2.1): a controllable non-linear stage on the body.
- **Click:** an embedded sample (§8) triggered at A0 + nudge. It has **Click Type** (index), **Click Level**, and a fixed HP at ~1 kHz so it cannot disturb the phase-critical band.
- **Kick Tone:** a gentle 1-pole tilt (optional, v1.1).

#### 5.2.1 Kick saturation stage

Signal path: `sine body → [pre-emphasis] → drive gain → shaper → [de-emphasis] → amp envelope (or before it, see Env Follow) → + click`.

- **Kick Drive** (0–1 → input gain 1–30×, i.e. 0 to +30 dB) with automatic output level compensation. Loudness stays roughly constant, so the knob changes character rather than volume.
- **Sat Type** (stepped):
  - **Soft** – `tanh`: smooth, odd harmonics only (clean psy "fat sine").
  - **Tube** – asymmetric soft clip `x ≥ 0: tanh(x)`, `x < 0: tanh(x·(1−a))/(1−a)`: adds even harmonics for warmth.
  - **Diode** – a harder knee (`x / (1 + |x|^n)^(1/n)`, n ≈ 2.5–4): a punchy, more "square" hi-tech kick.
  - **Tape** – a soft shaper plus a tiny amount of level-dependent HF loss (a 1-pole LP whose cutoff drops with drive), used only above 1 kHz.
- **Bias** (−1 … +1): adds a DC offset before the shaper, which sets the asymmetry and so the even-harmonic amount. The static offset `shaper(bias)` is subtracted **analytically** after the shaper. No DC-blocking high-pass is used on the kick, because an HP near 5–20 Hz would shift the phase of a 40–60 Hz fundamental and break the anchors.
- **Env Follow** (0–1): how far the drive follows the amplitude envelope. At 0 the saturation sits **after** the amp envelope, so the attack is driven hard and the tail cleans up as it decays, as in hardware. At 1 it sits **before** the envelope and the whole kick is equally saturated.
- **Sat Tone** (−1 … +1): a tilt applied as a matched pre-/de-emphasis pair around the shaper, with corner ≥ 300 Hz. It changes which harmonics get driven, but for small (linear) signals the pair cancels. The 30–90 Hz band stays phase-neutral.
- **Oversampling:** the shaper runs 4× oversampled (polyphase half-band IIR/FIR pair, own implementation), because the sweep starts at up to ~3 kHz and hard shapes alias otherwise. The kick is a single voice, so the cost is small. The resampler's group delay is compensated so the click and body stay aligned.

**Phase safety:** a memoryless non-linearity applied to a sine creates harmonics phase-locked to it, so the **fundamental keeps its phase** and the anchors stay valid at any drive setting. Only the emphasis filters (kept ≥ 300 Hz) and the oversampling filters (delay-compensated) could shift it. The anchor test (§12) runs at max drive for every Sat Type to guard this. (Strictly, this holds for a steady sine. During the sweep and decay the harmonics stay locked to the instantaneous phase, which is what matters at the anchors.) Caveat: with Bias ≠ 0 the *static* offset is removed analytically, but a slow envelope-following DC component remains. It is part of the "thump" of asymmetric drive. Env Follow and Bias ranges are limited so it stays below −30 dB of the fundamental, and this is checked in tests.

### 5.3 Bass voice (analog-style)

- **Oscillator:** PolyBLEP falling saw ↔ pulse morph (**Wave**). Phase is set exactly at note-on (§2.3). The reset discontinuity falls where the previous note is already silent, and the new note's attack hides its own start step.
- **Sub:** a sine at the bass pitch, same phase variable (**Sub** level). Optionally one octave down (phase = ½ of the grid phase).
- **Filter** (TPT/ZDF topology, Zavalishin), selectable:
  - **Ladder 24** (default): 4-pole Moog-style with tanh input stage, resonance, and passband gain compensation. Input gain ("Drive") changes character, as the forums note.
  - **OTA 12:** 2-pole SVF LP, a cleaner Juno/Virus-ish tone.
  - **Diode** (v1.1): port of Acidus' diode ladder for Goa acid (needs its 8× oversampling).
  - Optional **2× oversampling** of filter + drive (build/runtime flag). Default cutoffs stay below ~4 kHz, so v1 can ship without it if CPU is a concern.
- **Bass Drive:** soft saturation after the VCA. **Tone EQ:** a fixed small dip at the 3rd harmonic (research tip) with a **3rd-H trim** knob.
- **Analog:** a bounded, seeded per-note variation of cutoff (±cents) and envelope times (±%). It **never** touches oscillator pitch or phase, and it is disabled on the first note after the kick when the amount is below 50 %. The seed is fixed per beat position so bounces are reproducible.

### 5.4 Output

Kick and bass are summed in mono and duplicated to stereo. There is a **Balance** knob (kick ↔ bass; default puts the kick slightly louder, per the forums) and a **Volume** knob, with a final gentle safety soft-clip (off by default). v1.1: optional stereo width on the bass above 200 Hz, plus two extra mono outputs (kick, bass) that stay phase-coherent.

## 6. Flow: automatic velocity and emphasis

Research consensus: nearly every KBBB fix is about the **first bass note after the kick**, which needs to be quieter or darker. After that come the relative levels of the three notes.

For each beat Kikset already knows, analytically:
- `K_n`: the kick's RMS inside step window n (from its amplitude envelope),
- `B_n`: each bass note's nominal RMS (from its envelopes, gate and filter).

**Auto gain per active bass step n:**

```
g_n = clamp( 1 − Flow · ( a·[n is first active after kick] + b·min(1, K_n / K_0 · κ) ), 0.2, 1 )
      · 2^( E_n · 0.5 )                         (E_n = emphasis, ±1 → ±6 dB)
E_n = Emph_n + Roll · (n − 2)                    (Roll tilts steps 1..3: <0 falling, >0 rising)
```

Defaults: a = 0.35, b = 0.65, κ = 2, **Flow** = 0.5. That gives about −3 dB on the first note after a typical kick, and less on later steps.

Emphasis also acts like a 303 accent: **Env Mod × (1 + 0.5·E_n)** and **cutoff + 0.3·E_n octaves**. The same number shapes level and brightness, which matches the forum advice (velocity → volume and cutoff).

**Push** (±10 ms) shifts all bass notes in time. The phase stays exact in Follow mode because the start phase is computed from the actual onset time. In Reset mode the solver retargets the anchor to the shifted onset.

A small **Flow meter** in the UI shows the resulting per-step gains (dB), so the automation is visible, not magic.

## 7. Host integration (CLAP)

**Plugin:** `com.holstebroe.kikset`, features `instrument`, `synthesizer`, `drum`, `mono`.

**Extensions:** `params`, `state`, `gui`, `audio-ports` (1× stereo out; v1.1 adds 2 mono aux), `note-ports` (1 input, CLAP + MIDI dialects), `latency` (0), `thread-check` if available, `render` (offline hint, optional).

**Timing:**
- Read `clap_process.transport`. If `CLAP_TRANSPORT_HAS_BEATS_TIMELINE` and `IS_PLAYING`, the beat position is `song_pos_beats / CLAP_BEATTIME_FACTOR`, advanced per sample by `tempo / 60 / fs`. Handle `CLAP_EVENT_TRANSPORT` mid-block.
- A kick triggers when the beat position crosses an integer, and a bass step when it crosses n/4. The crossing time is computed with a **fractional-sample** offset so the start phase is sub-sample exact.
- **Jump/loop detection:** if the host position differs from the predicted one by > 1 sample, resync. Bass waits for the next step boundary and the kick for the next beat (no mid-beat starts).
- **Tempo changes** are picked up at each kick trigger (the whole beat uses one T16). Tempo ramps are therefore piecewise constant per beat, which is inaudible at psy tempos.

**Play modes** (param):
- **Host** (default): plays whenever the transport is playing. A held MIDI note overrides the root.
- **MIDI Gate:** plays only while a note is held; the note sets the root. When the transport is stopped, an internal clock starts at note-on using the host tempo (or 145 BPM).

**Threading:** the same pattern as Acidus. There is a lock-free param queue (GUI → audio via host `request_flush`, audio → GUI via atomics). The audio thread writes the last rendered beat (min/max per column) plus the anchor positions into a double buffer for the scope. When stopped, the GUI calls the pure `renderBeatPreview(params, tempo, root)` on its own thread.

**State:** versioned binary or plain key=value blob containing param values and the chosen click index. Unknown ids are ignored, so older and newer projects load.

## 8. Embedded click samples

- A set of 8–12 short clicks (≤ 30 ms, mono, 16-bit, 48 kHz; ≈ 25–35 KB total): tick, tok, snap, tap, FM blip, noise burst, "909-ish", "hi-tech".
- The set is **self-made** to avoid licensing issues. `tools/make_clicks.py` synthesises them deterministically (filtered impulses, FM, noise bursts with fast envelopes), and they can be replaced by recorded clicks later. Source WAVs live in `resources/clicks/`.
- **Embedding without external tools:** `cmake/EmbedResources.cmake` reads each WAV with `file(READ … HEX)` and writes `generated/ClickData.cpp` containing `constexpr int16_t` arrays plus a name table. C++23 `#embed` is not relied on because compiler support is uneven.
- At activation (sample-rate change) the clicks are resampled once to the host rate with a windowed-sinc interpolator, off the audio thread.

## 10. GUI

The GUI is a custom pixel-rendered panel reusing Acidus' `Graphics`, `Font`, `ControlRenderer` and per-OS `GuiWindow` (X11 / Win32 / Cocoa). Size is about 900 × 560 logical px, with 2× supersampling as in Acidus.

```
┌──────────────────────────────────────────────────────────────────────────────┐
│ KIKSET                         Key [F]  Mode [Host]  Phase [Reset|Follow]     │
├──────────────────────────────────────────────────────────────────────────────┤
│  WIDE SCOPE — one beat (4 × 1/16), full panel width                          │
│   K                 │ B1               │ B2               │ B3               │ │
│  ▓▓▒▒░░~~~~--       │ ██▆▅▃▂__         │ ██▆▅▃▂__         │ ██▆▅▃▂__         │ │
│  kick = orange      bass = green     overlap = both drawn     │ = anchors     │
│  pitch-curve overlay (thin line)  • settle point  ▲ tail gate  ◆ flow gain dB   │
├───────────────────────────┬──────────────────────────────────────────────────┤
│  ┌───┐ ┌───┐ ┌───┐ ┌───┐  │ handoff zoom ±3 ms @ first anchor                │
│  │ K │ │ B │ │ B │ │ B │  │ solver: nudge 1.4 ms  Δpitch −12 c  Δφ 3°        │
│  └───┘ └───┘ └───┘ └───┘  │                                                  │
│         (o)   (o)   (o)   │ FLOW (o) ROLL (o) PUSH (o) GEL (o) LOCK (o)      │
│         emph  emph  emph  │ BAL (o) VOL (o)                                  │
├───────────────────────────┴──────────────────────────────────────────────────┤
│ KICK  Tune Sweep Curve Punch Settle Length Shape Fish │ Click▾ Lvl            │
│ DRIVE Drive  Type▾  Bias  EnvFollow  Tone                                      │
│ BASS  Wave Sub Cutoff Res EnvMod F.Dec Attack Snap Gate Drive Analog          │
└──────────────────────────────────────────────────────────────────────────────┘
```

**Wide scope** (full panel width, ~880 × 150 px): it shows exactly one beat = 4/16 notes, with the time axis split into the four step lanes and the anchors drawn as vertical lines.
- The **kick is drawn in one colour (orange) and the bass in another (green)** as separate traces, from separate per-voice buffers rather than the mix. Where they overlap (Gel, or Follow mode with a long kick), both are visible, and an optional faint white trace shows their sum.
- Rendering is min/max per pixel column (one column ≈ 0.12 ms at 145 BPM, 880 px) with amplitude on a linear scale and an optional log (dB) toggle, so the low-level kick tail stays visible.
- Overlays: the kick pitch-curve (thin line, right axis in Hz), the settle point, the tail gate (Reset mode), the per-step Flow gains, and a small ✓/Δ badge at each anchor showing the phase error (normally 0.0°).
- **Data source:** during playback the audio thread publishes the last completed beat (per-voice min/max arrays + anchor data) into a triple buffer, at most once per beat, so no allocation or locking happens on the audio thread. When stopped, the GUI thread renders a preview beat with the pure `renderBeatPreview()` function whenever a parameter changes. The scope therefore responds to knob moves even without playback.
- The playhead sweeps across the scope during playback, and the step buttons light up in sync.

- Step buttons light up in time with playback (beat-position atomic from the audio thread). The K step is always on.
- The scope shows the **pitch curve overlay** for the kick sweep and marks the settle point and tail gate. Dragging on the scope edits Curve and Punch (optional, v1.1).
- Knob interaction, fine-drag with Shift and double-click reset follow Acidus conventions.

## 12. Test plan

| Test | Pass criterion |
|---|---|
| **Anchor exactness** (all 12 keys × 130–180 BPM in 1 BPM steps × Lock Style {0, 0.5, 1} × both phase modes) | Rendered phase at locked anchors within 1e‑6 cycles of target (from the analytic phase); solver converges; adjusters inside ranges |
| **Audio-domain anchor check** (`analyze_render.py`) | Instantaneous phase (Hilbert, 30–90 Hz band) at anchors matches target within ±2° |
| **Determinism** | Beat N and beat N+100 bit-identical (Analog seeded by step index) |
| **Saturation phase safety** (every Sat Type × Drive 1.0 × Bias ±1 × Tone ±1) | Fundamental phase at anchors unchanged within ±1° vs. Drive 0; no DC drift > −60 dBFS |
| **Scope data** | Per-voice buffers match offline renders; the audio thread publishes without allocation or locking |
| **Handoff continuity** | No discontinuity > −60 dBFS in 30–90 Hz band at locked anchors (Follow mode) |
| **Reset tail gate** | Kick amplitude = 0 before the next active anchor in Reset mode |
| **Flow** | First-after-kick gain within spec; toggling steps moves "first" correctly |
| **Transport** | Loop/jump/tempo change → no clicks, correct resync; stopped transport + MIDI Gate works |
| **Robustness** | Hostile params/events/state never produce NaN/Inf (as Acidus) |
| **Perf** | < 1 % of one core at 48 kHz (single voice) on CI runners |
| **Listening A/B** | 3 tempos × 3 keys, Reset vs Follow, Lock Style extremes, against reference tracks |

## 14. Open questions

1. **Default phase mode:** Reset (classic) or Follow (coherent)? Decide by listening at milestone 2.
2. **Solver cost weights:** how audible is a 2 ms kick nudge compared with a 20-cent change in start pitch? Tune by ear; expose Lock Style.
3. **Tempo-relative kick sweep:** scaling sweep times with tempo keeps the groove consistent but changes kick timbre by ~±5 % across 140–150 BPM. Alternative: sweep in ms, and only Settle/Length in T16.
4. **Flow loudness measure:** plain RMS or K-weighted? Start with RMS of the 30–300 Hz band.
5. **Triplet grid (KBB forest/dark):** v1 is 16ths only. Supporting 3 steps per beat mainly means changing `T_step = T_beat/3`, since the solver and anchors are grid-agnostic. This is a cheap v1.1 win.
6. **Parameter naming** in the host generic UI, and module paths (`Kick/…`, `Bass/…`, `Feel/…`).
